\subsection{ภาพรวมการประกอบ}
\label{subsec:mech_overview}

การประกอบชิ้นส่วนทางกลของหุ่นยนต์แบ่งออกเป็น 3 ชิ้นส่วนย่อย (Sub-assemblies) หลัก เพื่อให้ง่ายต่อการตรวจสอบ ลดข้อผิดพลาดในขั้นตอนการประกอบ และสะดวกต่อการซ่อมบำรุงในอนาคต ได้แก่ ส่วนฐาน (Base), ส่วนแขนกลและมอเตอร์ (Arm \& Motor) และชุดเอ็นโค้ดเดอร์ (Encoder Sub-assembly) 

ชิ้นส่วนหลักอื่นๆ ที่จะถูกนำมาประกอบรวมในภายหลังประกอบด้วย ชุดมือจับ (Gripper), สายพานส่งกำลัง (Belt), คัปปลิ้ง (Coupling) และเพลาเชื่อมต่อเอ็นโค้ดเดอร์สนาม (Field Encoder Shaft) เครื่องมือหลักที่ใช้ในการประกอบประกอบด้วย ประแจหกเหลี่ยม ประแจปากตาย ประแจแหวน และค้อนยาง

ขั้นตอนการประกอบส่วนฐาน:
\begin{enumerate}
    \item \textbf{การประกอบโครงสร้างฐาน (Base):} นำอลูมิเนียมโปรไฟล์ $20\times40$\,mm ทั้ง 4 ชิ้น มาประกอบเข้ากับแผ่นชิ้นฐานหุ่น (Base Plate) โดยจัดวางให้อลูมิเนียมโปรไฟล์สวมลงในร่องของแผ่นฐานพอดี จากนั้นใช้สกรู M5 ยาว 12\,mm จำนวน 8 ตัว ขันยึดให้โครงสร้างตั้งฉากและแน่นหนา
    \item \textbf{การติดตั้งแผ่นรอง (Pulley Mounting Plate):} นำแผ่นชิ้นรอง Pulley มาประกอบปิดทับอลูมิเนียมโปรไฟล์จากทางด้านบน จัดให้รูน็อตของโปรไฟล์และแผ่นชิ้นรองตรงกัน ใช้สกรู M5 ยาว 12\,mm จำนวน 8 ตัว ขันยึดโครงสร้างทั้งหมด
    \item \textbf{การวางพูลเลย์ (Pulley Placement):} วาง Pulley 72 ฟัน ลงในตำแหน่งแกนกลางของแผ่นชิ้นรอง โดยหมุนจัดให้รูน็อตของทั้งสองชิ้นตรงกัน
    \item \textbf{การยึดเสื้อลูกปืน (Bearing Mounting):} นำ Bearing Mounting วางลงไปที่ตำแหน่งแกนกลางของ Pulley จัดรูน็อตให้ตรง ยึดชิ้นส่วนทั้งหมดเข้ากับโครงสร้างฐานด้วยสกรู M4 ยาว 40\,mm จำนวน 3 ตัว แล้วขันล็อกด้วยน็อตตัวเมีย (Nut) ให้แน่น
    \item \textbf{การติดตั้งตลับลูกปืน (Bearing Installation):} สวมตลับลูกปืนเม็ดเรียว (Tapered Roller Bearing) เข้าไปด้านบนของ Bearing Mounting และนำตลับลูกปืนเม็ดกลม (Ball Bearing) ใส่เข้าไปที่รูแกนกลางบริเวณใต้แผ่นชิ้นรอง Pulley
    \item \textbf{การติดตั้งชิ้นส่วนอ้างอิง (Set Home):} นำชิ้นส่วน Set Home ประกอบเข้ากับ Bearing Mounting บริเวณรูน็อตที่ยังว่างอยู่ ใช้สกรู M4 ยาว 40\,mm ยึดและขันล็อกให้แน่นด้วยน็อตตัวเมีย
\end{enumerate}

ขั้นตอนการประกอบส่วนแขนกล:
\begin{enumerate}
    \item \textbf{ประกอบโครงแขน:} นำแผ่นชิ้นส่วนแขนกลบนและล่าง มาประกบเข้ากับเหล็กกล่อง Galvanized โดยใช้บูชรอง (M5 OD $10\times25$\,mm) เพื่อรักษาระยะห่าง และใช้บูชรอง (M6 OD $8\times2$\,mm) อุดพื้นที่ว่างบริเวณด้านบนเหล็กกล่อง จากนั้นร้อยสกรู M5 แล้วขันล็อกด้วยน็อตให้แน่น
    \item \textbf{ติดตั้งระบบขับเคลื่อน:} ติดตั้งมอเตอร์เข้ากับแผ่นแขนกล จากนั้นสวม Pulley 20 ฟัน เข้ากับเพลามอเตอร์
    \item \textbf{ติดตั้งแกนหมุนหลัก:} สอด Stepped Shaft เข้ากับจุดหมุนหลักของแขน โดยใส่ Key (ลิ่ม $5\times5\times8$\,mm) เพื่อป้องกันการหมุนฟรีของเพลา จากนั้นติดตั้ง Shaft Support เพื่อประคองแกนเพลาให้มั่นคง
    \item \textbf{ติดตั้งอุปกรณ์เสริม:} ติดตั้งลูกกลิ้งประคองสายพาน (Idler) ด้วยบูชรองและสกรูที่กำหนด พร้อมทั้งติดตั้ง Proximity Sensor สำหรับใช้เป็นเซนเซอร์อ้างอิงตำแหน่ง (Homing Limit)
    \item \textbf{ตรวจสอบ:} ตรวจเช็คการประกอบโดยขันน็อตทุกจุดให้แน่นตามค่าแรงบิด (Torque) ที่เหมาะสม และตรวจสอบความราบรื่นในการเคลื่อนที่ของข้อต่อ
\end{enumerate}

\end{enumerate}

\subsection{การประกอบรวมขั้นสุดท้าย (Final Assembly Process)}
\label{subsec:final_assembly}

หลังจากประกอบชิ้นส่วนย่อยเสร็จสิ้น ดำเนินการประกอบรวมเป็นหุ่นยนต์เต็มรูปแบบตามลำดับดังนี้:

\begin{enumerate}
    \item \textbf{การติดตั้งเอ็นโค้ดเดอร์เข้ากับฐาน:} นำชุดเอ็นโค้ดเดอร์ไปประกอบเข้ากับส่วนฐาน ขันน็อตยึดเข้ากับรูต๊าปเกลียวบนฐานให้แน่นหนา
    \item \textbf{การใส่สายพาน:} นำชุดฐานที่ยึดเอ็นโค้ดเดอร์แล้ว มาทำการคล้องสายพาน (Belt) เตรียมไว้สำหรับการส่งกำลัง
    \item \textbf{การประกอบแขนกลและมอเตอร์:} นำส่วนแขนกลและมอเตอร์ประกอบเข้ากับฐาน โดยสอดเพลาของส่วนแขนกลลงในรูร้อยแกนกลางของส่วนฐาน
    \item \textbf{การตั้งค่าพรีโหลดตลับลูกปืน (Bearing Preload):} จัดวางให้ส่วนแขนกลและมอเตอร์กดทับลงบนตลับลูกปืนเม็ดเรียวของส่วนฐาน ขันน็อตที่เพลาบริเวณด้านบนสุดและบริเวณก่อนเข้าชุดเอ็นโค้ดเดอร์ เพื่อสร้างแรงดึงล่วงหน้า (Preload) ซึ่งจะช่วยลดระยะคลอน (Backlash) ของกลไกได้อย่างมีนัยสำคัญ
    \item \textbf{การเชื่อมต่อเอ็นโค้ดเดอร์สนาม:} นำเพลาเชื่อมต่อมาต่อเข้ากับเพลาบริเวณด้านบนสุดของหุ่นยนต์ ใช้คัปปลิ้ง (Rigid/Flexible Shaft Coupling) ยึดเพื่อให้สามารถอ่านค่าตำแหน่งการหมุนของเพลาได้อย่างแม่นยำ
    \item \textbf{การติดตั้งชุดมือจับ (Gripper):} นำชุดมือจับประกอบเข้ากับปลายแขนของหุ่นยนต์ ยึดด้วยน็อต 3 ตัว และขันล็อกให้แน่นหนาด้วยน็อตกันคลาย (Lock Nut)
\end{enumerate}

\subsection{แนวทางปฏิบัติในการเดินสายไฟ (Cable Management \& Wiring)}
\label{subsec:cable_management}

การเดินสายภายในและภายนอกตู้ควบคุมใช้มาตรฐานการเดินสายอุตสาหกรรม โดยมีข้อกำหนดดังต่อไปนี้:

\begin{itemize}
  \item \textbf{การเลือกขนาดสายไฟ (Wire Sizing):} 
        วงจรขับมอเตอร์ (24V Bus) ใช้สายไฟขนาด 16 AWG เพื่อรองรับกระแสสูงสุด (Peak Current) ได้ถึง 10A โดยไม่เกิด Voltage Drop ที่มีนัยสำคัญ ส่วนวงจรลอจิกและเซนเซอร์ (5V Bus) ใช้สายไฟขนาด 22-24 AWG 
  \item \textbf{การเผื่อระยะสายบริเวณจุดหมุน (Service Loop):} 
        บริเวณข้อต่อของแขนกล (Joints) มีการเผื่อความยาวของสายไฟ (Slack) ในรูปแบบของ U-loop เพื่อให้สายไฟสามารถโค้งงอได้อย่างอิสระ ป้องกันแรงดึงรั้ง (Tension) ที่จะทำให้ทองแดงภายในขาดล้า (Fatigue) เมื่อหุ่นยนต์เคลื่อนที่ไปจนถึงมุมสูงสุด (Maximum Reach)
  \item \textbf{รัศมีการโค้งงอ (Bending Radius) และการนำสาย:} 
        ติดตั้งชิ้นส่วน 3D Print บริเวณขอบและมุมของโครงสร้างหุ่นยนต์ เพื่อบังคับให้สายโค้งงอด้วยรัศมีที่มากกว่า 4 เท่าของเส้นผ่านศูนย์กลางสายไฟ ป้องกันการหักมุมแคบซึ่งจะทำลายฉนวนหุ้มสายสัญญาณภายใน
  \item \textbf{การแยกรางสายไฟ (Trunking Separation):}
        สายสัญญาณจาก Encoder (ที่มีความไวต่อ Noise สูง) จะถูกเดินแยกท่อหรือรางสายไฟออกจากสาย Power ของมอเตอร์อย่างเด็ดขาด เพื่อป้องกันคลื่นแม่เหล็กไฟฟ้า (EMI) เหนี่ยวนำเข้าสู่สายสัญญาณ
\end{itemize}

\subsection{ภาพรวมสถาปัตยกรรมซอฟต์แวร์ (Software Architecture)}

\subsection{การจัดสรรเวลาทำงาน (Execution Model และ Task Timing)}
\label{subsec:execution_model}

ระบบควบคุมใช้วิธีการจัดสรรเวลาแบบ Hard Real-Time โดยใช้ตัวตั้งเวลา TIM6 เป็นตัวกำหนด Base Rate ที่ 1\,kHz วงรอบการควบคุมถูกแบ่งออกเป็น 2 ความถี่ผ่าน Software Counter ภายใน Interrupt Service Routine (ISR) เดียวกัน เพื่อหลีกเลี่ยงปัญหาการสลับบริบท (Context Switching)

\begin{itemize}
  \item \textbf{ทุก 1\,ms (1\,kHz - Inner Loop):} 
        ทำงานใน \texttt{MotorCtrl\_Tick1kHz()} เริ่มจากการอ่านค่าตำแหน่ง Encoder จาก TIM3 นำไปผ่าน Kalman Filter เพื่อประมาณค่าความเร็วและความเร่ง จากนั้นคำนวณ Velocity Inner PID และ Feedforward ตรวจสอบเงื่อนไขความปลอดภัย ก่อนส่งค่า PWM อัปเดตไปยัง TIM1 
  \item \textbf{ทุก 10\,ms (100\,Hz - Outer Loop):} 
        ทำงานใน \texttt{MotorCtrl\_Tick100Hz()} และ \texttt{HwIo\_Poll100Hz()} รับผิดชอบการกรองสัญญาณรบกวน (Debounce) ของเซนเซอร์ ประมวลผลสมการ S-Curve Trajectory และ ZVD Input Shaper เพื่อสร้าง Setpoint สำหรับ Position Outer PID
\end{itemize}

นอกจากการประมวลผลใน ISR แล้ว ในส่วนของ \textbf{Main Loop Context} จะทำงานแบบปล่อยอิสระ (Free-running) ใช้เวลาประมาณ $20\,\mu\text{s}$ ต่อรอบ ทำหน้าที่ตรวจสอบ Application FSM, จัดการข้อมูล Modbus ใน Ring Buffer, อัปเดตข้อมูล CAN Bus และส่งสัญญาณ Heartbeat

    \item \textbf{STATE\_INIT:} สถานะเริ่มต้นเมื่อเปิดเครื่อง เพื่อเตรียมความพร้อมของ Peripheral
    \item \textbf{STATE\_HOMING:} สถานะค้นหาจุดอ้างอิงศูนย์ ระบบจะไม่ยอมรับคำสั่งเคลื่อนที่อื่น

\end{itemize}

\subsection{กระบวนการหาจุดอ้างอิงระดับความแม่นยำสูง (Two-Stage Homing Sequence)}
\label{subsec:homing_sequence}

เพื่อขจัดปัญหาความคลาดเคลื่อนของตำแหน่งที่เกิดจากความหน่วงของเซนเซอร์ (Sensor Latency) ระบบจึงใช้วิธีการหาจุดอ้างอิงแบบ 2 ขั้นตอน (Two-Stage Industrial Homing) โดยอาศัยหลักการหาจุดกึ่งกลาง (Midpoint) ของขอบสัญญาณ (Edge) ทั้งสองด้าน

% รูปที่: กราฟความเร็วและสัญญาณเซนเซอร์ระหว่างทำ Homing
% ชื่อไฟล์แนะนำ: fig_homing_sequence.png หรือ .pdf
% เนื้อหา: กราฟแสดงช่วง FAST_SEARCH, BACKOFF, PREC_EDGE_A, FIND_EDGE_B และ GO_CENTER
% -----------------------------------------------------------------------

% \end{figure}

กระบวนการแบ่งเป็น 8 ขั้นตอนย่อยดังนี้:
\begin{enumerate}
    \item \textbf{FAST\_SEARCH:} หุ่นยนต์เคลื่อนที่กวาดเพื่อค้นหาพื้นที่ของ Proximity Sensor ด้วยความเร็วสูง (Coarse Search)
    \item \textbf{BACKOFF:} เมื่อเจอขอบสัญญาณ ระบบจะถอยหลังออกด้วยระยะเผื่อ (Clearance Margin)
    \item \textbf{PREC\_EDGE\_A:} เคลื่อนที่เข้าหาเซนเซอร์ด้วยความเร็วต่ำสม่ำเสมอ บันทึกตำแหน่งที่สัญญาณขอบขาขึ้น (Rising Edge) ปรากฏเป็นตำแหน่ง \textit{Edge A}
    \item \textbf{PREC\_OVERSHOOT:} เคลื่อนที่ทะลุผ่านเซนเซอร์จนสัญญาณดับลง เพื่อป้องกันการอ่านขอบสัญญาณผิดพลาดซ้ำซ้อน
    \item \textbf{FIND\_EDGE\_B:} เคลื่อนที่ถอยหลังกลับด้วยความเร็วต่ำสม่ำเสมอ บันทึกตำแหน่งที่สัญญาณขอบขาขึ้นปรากฏเป็นตำแหน่ง \textit{Edge B}
    \item \textbf{GO\_CENTER \& SETTLE:} คำนวณจุดกึ่งกลาง $\frac{\text{Edge A} + \text{Edge B}}{2}$ แล้วสั่งให้หุ่นยนต์เคลื่อนที่ไปยังจุดนั้น ระบบจะหน่วงเวลา 1 วินาที และกำหนดให้ตำแหน่งปัจจุบันเป็น 0 (Zero) 
\end{enumerate}
วิธีการนี้รับประกันได้ว่าตำแหน่งศูนย์ทางกล (Mechanical Zero) จะไม่เอนเอียงไปตามทิศทางการเคลื่อนที่หรือความเร็วในการตรวจจับ

\subsection{อัลกอริทึมควบคุมการเคลื่อนที่ (Motion Control Algorithms)}
\label{subsec:motion_control}

\subsubsection{S-Curve Trajectory และ ZVD Input Shaper}

ระบบสร้างโพรไฟล์การเคลื่อนที่แบบ S-Curve เพื่อจำกัดความเร็วสูงสุด (7.30\,rad/s), ความเร่งสูงสุด (27.49\,rad/s$^2$) และค่า Jerk (1400\,rad/s$^3$) อย่างเคร่งครัด จากนั้นนำ Setpoint ที่ได้ไปผ่าน ZVD Input Shaper ที่ทำงานแบบ Circular Buffer เพื่อลดการสั่นทอนที่ความถี่ธรรมชาติ $f_n = 12.13$\,Hz ตาม\cref{eq:zvd_impl}

\begin{equation}
  r_{shaped}(t) = 0.2832\,r(t) + 0.4981\,r(t - t_2) + 0.2189\,r(t - t_3)
  \label{eq:zvd_impl}
\end{equation}

โดยกำหนดให้ระยะหน่วง $t_2 = 4$\,steps และ $t_3 = 8$\,steps (ที่ความถี่ 100\,Hz)

\subsubsection{Steady-State Kalman Filter}

เนื่องจากการหาอนุพันธ์ของตำแหน่งจาก Encoder สร้างสัญญาณรบกวนความถี่สูง ระบบจึงใช้ Kalman Filter 4 สถานะ $\mathbf{x} = [\theta, \omega, \alpha, j]^\top$ ทำงานทุก 1\,ms เพื่อประมาณค่าความเร็วและความเร่ง ค่า Steady-State Gain ($\mathbf{K}_\infty$) ถูกคำนวณล่วงหน้าผ่านการแก้สมการ DARE (Discrete Algebraic Riccati Equation) บน MATLAB เพื่อลดภาระการคำนวณของไมโครคอนโทรลเลอร์

\begin{equation}
    \hat{\mathbf{x}}_{k|k} = \mathbf{A}_d\,\hat{\mathbf{x}}_{k-1} + \mathbf{B}_d\,u_{k-1} + \mathbf{K}_\infty(y_k - \mathbf{C}\hat{\mathbf{x}}_{k|k-1})
    \label{eq:kalman_update}
\end{equation}

\subsubsection{Cascade PID (Discrete Tustin)}

ระบบควบคุมแบบวงรอบซ้อน (Cascade PID) ใช้สมการแบบ Tustin (Bilinear Approximation) สำหรับ Velocity Inner Loop (1\,kHz) มีการประยุกต์ใช้ Anti-windup (Back-calculation) เพื่อป้องกัน Integral Windup เมื่อ PWM เข้าสู่ขอบเขตการอิ่มตัว $\pm 50$ 

\begin{equation}
  u_{vel}[k] = K_{p,v}\,e_v[k] + \text{integ}[k] + K_{d,v}\frac{e_v[k]-e_v[k-1]}{T_v}
  \label{eq:pid_vel}
\end{equation}
\begin{equation}
  \text{integ}[k] = \text{integ}[k-1] + K_{i,v}\,e_v[k]\,T_v + K_{t,aw}(u_{sat}[k] - u_{pre}[k])\,T_v
  \label{eq:pid_antiwindup}
\end{equation}
ส่วน Position Outer Loop (100\,Hz) จะคำนวณ Setpoint เชิงความเร็วเพื่อป้อนให้กับ Inner Loop ค่า Gain ที่ใช้ใน Firmware แสดงใน\cref{tab:pid_gains}

\subsection{ระบบความปลอดภัยทางซอฟต์แวร์ (Safety Stack)}
\label{subsec:safety_stack}

เพื่อป้องกันความเสียหายต่อกลไกและมอเตอร์ Firmware มีการตรวจจับความผิดปกติ 4 ระดับและจะบังคับให้ FSM เปลี่ยนเป็น \texttt{STATE\_FAULT} ทันที:
\begin{itemize}
    \item \textbf{Encoder Disconnect Guard:} หากระบบจ่าย PWM เกินระดับที่กำหนด (PWM $> 5$) ต่อเนื่องเป็นเวลา 200\,ms แต่ตำแหน่ง Encoder ไม่มีการเปลี่ยนแปลง ระบบจะพิจารณาว่าสาย Encoder ขาดหรือขั้วหลุดหลวม
    \item \textbf{Overcurrent Fuse:} อ่านกระแสจากเซนเซอร์ WCS1800 ผ่าน ADC (PA0) หากกระแสสูงกว่า 2.0\,A ต่อเนื่อง 100\,ms จะตัดการทำงาน (จำลองการทำงานของฟิวส์หน่วงเวลา)
    \item \textbf{Tracking Error Guard:} ตรวจสอบความแตกต่างระหว่าง Position Setpoint และตำแหน่งจริง หากคลาดเคลื่อนเกิน 10 องศา ต่อเนื่อง 50\,ms ระบบจะถือว่าเกิดการติดขัดทางกล (Mechanical Jam)
    \item \textbf{Boundary Limits:} จำกัดพื้นที่การทำงานผ่านซอฟต์แวร์ที่ระยะ 540 องศา เพื่อป้องกันปัญหาสายเคเบิลม้วนพันกัน (Cable Over-twist)
\end{itemize}

\subsection{การสื่อสารผ่านโครงข่ายและ CAN Bus Failsafe}
\label{subsec:comms_canbus}

ระบบรองรับการควบคุมจาก 2 แหล่ง ได้แก่ ESP32 Bluetooth Gamepad (ผ่าน USART3) สำหรับโหมด Manual และระบบ PC Backend (ผ่าน LPUART1 โปรโตคอล Modbus RTU) สำหรับโหมด Automation โดยมีการส่งสัญญาณ Heartbeat ข้ามไปมา 

ชุดหัวจับ (Gripper) ควบคุมผ่านเครือข่าย \textbf{FDCAN1} ด้วยความเร็ว 500\,kbps ซึ่งทำหน้าที่เป็น I/O Node (ID 0x10) ในกรณีที่ Node ไม่ได้รับสัญญาณ Heartbeat จาก Master ภายในเวลา 2 วินาที (2000\,ms) ระบบจะมี \textbf{CAN Watchdog Failsafe} ทำหน้าที่ตัดไฟ Relay ทั้งหมดโดยอัตโนมัติ ทำให้สปริงดึงกลไกกลับสู่สภาวะปลอดภัย

\subsection{ภาพรวมสถาปัตยกรรมระบบ (System Architecture)}
\label{subsec:system_architecture}

การบูรณาการหุ่นยนต์ (System Integration) ครอบคลุมการเชื่อมต่อส่วนประกอบทางฮาร์ดแวร์ ซอฟต์แวร์ และโครงข่ายการสื่อสารเข้าด้วยกันเป็นระบบเดียว สถาปัตยกรรมแบบ Cyber-Physical System ของหุ่นยนต์แสดงใน\cref{fig:system_architecture} ซึ่งแบ่งออกเป็น 4 ส่วนหลัก ได้แก่ 

\begin{enumerate}
    \item \textbf{Base System (PC Master):} ทำหน้าที่เป็นศูนย์กลางการสั่งการระดับสูงผ่าน Python Backend และ Web Dashboard
    \item \textbf{Main Controller:} ไมโครคอนโทรลเลอร์ STM32G474RE ทำหน้าที่ประมวลผลอัลกอริทึมควบคุมการเคลื่อนที่ (Motion Control) และ Application FSM
    \item \textbf{Actuators \& Sensors:} มอเตอร์ขับเคลื่อน, ชุดหัวจับ, เอ็นโค้ดเดอร์ และเซนเซอร์วัดกระแส
    \item \textbf{Subsystems:} เครือข่าย CAN Bus สำหรับควบคุมชุดหัวจับ และระบบ ESP32 สำหรับรับคำสั่งจากจอยสติ๊กไร้สาย
\end{enumerate}

\subsection{การจัดการข้อมูลร่วม (Shared Data Architecture)}
\label{subsec:shared_data}

Firmware ถูกออกแบบให้มีการแลกเปลี่ยนข้อมูลผ่านโครงสร้างตัวแปรส่วนกลาง \texttt{g\_robot} (\texttt{RobotState\_t}) ซึ่งทำหน้าที่เป็น Single Source of Truth ดังแสดงใน\cref{fig:firmware_flow} 

กลยุทธ์การจัดการข้อมูลแบ่งออกเป็นสองระดับ:
\begin{enumerate}
    \item \textbf{Interrupt Context (High Priority):} โมดูล \texttt{motor\_controller} และ \texttt{lib\_kalman} จะทำหน้าที่อ่านและเขียนข้อมูลสถานะการเคลื่อนที่ (เช่น \texttt{position\_counts}, \texttt{velocity\_rps}) ลงใน \texttt{g\_robot} โดยตรงด้วยความถี่ 1\,kHz เพื่อให้แน่ใจว่าลูปควบคุมทำงานด้วย Time-step ที่คงที่
    \item \textbf{Main Loop Context (Low Priority):} โมดูลสื่อสาร (\texttt{modbus\_bridge}, \texttt{canbus\_node}, \texttt{joystick}) จะทำการอ่านข้อมูลล่าสุดจาก \texttt{g\_robot} เพื่อส่ง Telemetry ไปยัง PC หรือรับคำสั่งใหม่เข้ามา ซึ่งช่วยลดความหน่วง (Latency) ของการประมวลผลคำสั่งสื่อสารที่อาจขัดจังหวะลูปการควบคุมหลักได้
\end{enumerate}

\subsection{การเชื่อมต่อ Base System และ Modbus RTU}
\label{subsec:modbus_integration}

ระบบสื่อสารระหว่างหุ่นยนต์และ Base System ใช้โปรโตคอล Modbus RTU ผ่านพอร์ต LPUART1 (230400 bps, 8N1) โดย STM32 ทำหน้าที่เป็น Slave Address 0x15 (21)

การสื่อสารฝั่ง Base System ถูกพัฒนาด้วย Python โดยมี \texttt{serial\_bridge.py} ทำหน้าที่เป็น Multiplexer เพื่อแยกข้อมูล Telemetry (เช่น ตำแหน่ง, ความเร็ว, ค่ากระแส) ส่งต่อไปยัง Web Dashboard ผ่าน WebSocket และแยกคำสั่ง Modbus ส่งผ่าน Virtual COM Port ไปยังระบบควบคุมระดับสูง การทำงานร่วมกันแบบนี้ช่วยแก้ปัญหาคอขวดของการสื่อสารผ่าน Serial Port เดียว

\subsection{การเชื่อมต่อ Motor, Encoder และ Motor Driver}
\label{subsec:motor_integration}

การประมวลผลสัญญาณฮาร์ดแวร์หลักเชื่อมต่อโดยตรงกับ Peripheral ของ STM32:
\begin{itemize}
    \item \textbf{Encoder AMT-103:} เชื่อมต่อผ่าน TIM3 ในโหมด Quadrature Encoder Interface (QEI) บนขา PB4 และ PB5 ให้ความละเอียด 8192 counts/rev
    \item \textbf{Cytron MD10C Driver:} รับสัญญาณ PWM จาก TIM1 (PA8) ด้วยความถี่ Switching ที่ 19.6\,kHz เพื่อหลีกเลี่ยงความถี่เสียงที่มนุษย์ได้ยิน (Audible Noise) และสัญญาณทิศทาง (DIR) ถูกส่งผ่าน Optocoupler Module เพื่อป้องกัน Ground Loop
    \item \textbf{Current Sensor (WCS1800):} เชื่อมต่อเข้ากับ ADC1 (PA0) ผ่านวงจร DMA Averaging (EMA Filter) เพื่ออ่านกระแสป้อนกลับเข้าสู่ Safety Stack
\end{itemize}

\subsection{การเชื่อมต่อ Joystick ผ่าน ESP32}
\label{subsec:joystick_integration}

ระบบรองรับการควบคุมแบบ Manual ผ่านจอยสติ๊ก Bluetooth โดยใช้ ESP32-DEVKIT-V1 เป็นตัวรับสัญญาณและถอดรหัส จากนั้นส่งคำสั่งในรูปแบบ ASCII Character ผ่าน USART3 (115200 bps, 8N1) ไปยัง STM32 

การสลับโหมดควบคุมระหว่าง Base System และ Joystick ทำได้ผ่านสวิตช์ฮาร์ดแวร์ โดยเมื่ออยู่ในโหมด Base System คำสั่งจาก Joystick จะถูกตัดออกทั้งหมด (Blocked) ยกเว้นปุ่ม \texttt{P/X} (Emergency Stop) และปุ่มสลับโหมด เพื่อให้มั่นใจได้ว่าระบบสามารถหยุดฉุกเฉินได้จากจอยสติ๊กไร้สายตลอดเวลา
\subsection{การเชื่อมต่ออุปกรณ์ขับเคลื่อนและเซนเซอร์ (Motor, Encoder \& Driver)}
\label{subsec:motor_integration}

การเชื่อมต่อในส่วนการขับเคลื่อนให้ความสำคัญกับความละเอียดในการวัดตำแหน่งและการป้องกันสัญญาณรบกวนทางไฟฟ้า ดังนี้:
\begin{itemize}
    \item \textbf{Encoder Interface:} ชุดเซนเซอร์ AMT-103 (ความละเอียด 2048 PPR) ถูกเชื่อมต่อผ่านโหมด Quadrature Encoder Interface (QEI) บน TIM3 ของ STM32 (ขา PB4 และ PB5) โดยใช้การอ่านแบบ $\times 4$ ทำให้ได้ความละเอียดสูงถึง 8192 counts ต่อรอบการหมุน
    \item \textbf{Motor Control:} มอเตอร์ขับเคลื่อนผ่าน Cytron MD10C ซึ่งรับสัญญาณ PWM จาก TIM1 CH1 (PA8) ที่ความถี่ 19.6\,kHz (ARR=50) เพื่อหลีกเลี่ยงสัญญาณรบกวนในย่านที่หูมนุษย์ได้ยิน ทั้งนี้สัญญาณควบคุมทิศทาง (DIR) ถูกส่งผ่าน PA9 โดยผ่าน Optocoupler Module เพื่อแยกกราวด์ (Galvanic Isolation) ระหว่างวงจรควบคุมและวงจรขับกำลังอย่างสมบูรณ์
\end{itemize}

\subsection{การสื่อสารด้วยโปรโตคอล Modbus RTU}
\label{subsec:modbus_integration}

ระบบสื่อสารกับ Base System ผ่านโปรโตคอล Modbus RTU บน LPUART1 (230400 bps, 8E1, RS-485) โดยกำหนดให้ STM32 เป็น Slave Address 21 (0x15) 

\textbf{สถาปัตยกรรม Backend:} Base System เปลี่ยนมาใช้ Python \texttt{asyncio} ร่วมกับ WebSocket Backend แทน \texttt{main.exe} เดิม เพื่อแก้ปัญหาภาวะ Abnormal Heartbeat ที่เคยพบในเวอร์ชันทดสอบที่ 1 โดยตัว Backend จะรับคำสั่งจาก Frontend ผ่าน WebSocket แล้วทำการแปลง (Translate) เป็น Modbus RTU Frame ส่งผ่าน Serial Port ไปยังระบบหุ่นยนต์

\textbf{Modbus Register Map:} ประกอบด้วยพื้นที่หน่วยความจำ 128 Registers แบ่งกลุ่มการใช้งานดังนี้:
\begin{itemize}
    \item \textbf{Status Registers:} สำหรับอ่านค่าตำแหน่ง (Position), ความเร็ว (Velocity) และสถานะของเครื่องจักร (FSM State) แบบ Real-time
    \item \textbf{Command Registers:} สำหรับรับค่าเป้าหมาย (Target Position), การเลือกโหมด (Mode) และคำสั่งการทำงานของชุดหัวจับ (Gripper Command)
\end{itemize}
การออกแบบเช่นนี้ช่วยให้การสื่อสารระหว่างคอมพิวเตอร์แม่ข่ายและตัวควบคุมระดับต่ำ (Embedded) มีความน่าเชื่อถือสูง แม้ในสภาวะที่มีการรับส่งข้อมูลจำนวนมาก
